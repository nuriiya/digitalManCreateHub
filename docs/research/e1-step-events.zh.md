# E1 实验记录：给每一步打上标记（阶段归属不再靠猜）

> 分支：`experiment/dsh-integration` · 日期：2026-09-15
> 依据：`docs/research/dsh-integration.zh.md` 的 E1 项
> 注意：本实验**不动既有设计**（design.md 未改），只在实现层加"标记 + 记录"。

## 解决的问题

对话里的进度手风琴要显示「每个阶段的模型交互」，但以前**做不到准确归属**：
- pipeline 事件流里只有「阶段开始/结束」和「模型调用」两类事件混在一起，
  前端只能靠**序号区间**（猜第几条到第几条属于哪个阶段）——事件缺失或乱序就归错
- 普通对话（不跑 pipeline）**一条明细都看不到**：事件记录依赖"任务号"，
  没有任务就不记

## 改了什么（6 处）

| # | 位置 | 改动 |
|---|---|---|
| 1 | `jobs.py` | 新增两个上下文标记：`set_node_context`（当前在跑哪个阶段）、`set_chat_context`（当前是哪次对话） |
| 2 | `llm.py:_notify` | 记录事件时**带上标记**；并且**没有任务也能记**（靠对话号归组，任务号留空） |
| 3 | `pipeline.py:_run_node` | 每个阶段执行期间打上"当前阶段"标记（用 try/finally 保证清理） |
| 4 | `chat.py` | ① 对话流开始时绑定对话标记；② 每次调模型**显式**记录"发给模型什么/模型回了什么"；③ 每次工具调用记录"调了什么工具、成不成功、结果摘要" |
| 5 | `jobs.py:events_since` + `main.py:/api/events` | 支持按**对话号**拉事件（新增 `session_id` 过滤） |
| 6 | 前端 `PipelineProgressCard.tsx` | 展开阶段时**优先用明确标记**归属，没有标记的旧数据退回序号区间；渲染"工具调用"条目 |

## 关键设计决定（踩坑记录）

**为什么对话场景不依赖"线程标记"**：对话流是生成器，被服务端线程池**分段执行**，
线程标记在分段之间会丢（第一次验证：只记下了工具调用，模型调用/回复全丢）。
第二版改为**显式传对话号**，问题消失。

## 验证结果

**对话场景（会话 406，短问题）**——5 条事件完整记录：
```
#3796 llm.call   发给 deepseek-v4-pro：射频天线这个部件，历史库里有可类比案例吗…
#3797 llm.reply  模型回复：<tool_call>{"name":"查询历史 FMEA",...}
#3798 tool.exec  工具「查询历史 FMEA」→ {"hits": 0, "items": []}
#3799 llm.call   工具结果回灌后的第二次调用
#3800 llm.reply  模型最终回答：没有。理由：检索「射频天线」0 条命中…
```
→ 对话页展开某个阶段，能看到**完整的"模型说→调工具→看结果→再回答"链条**。
