# 检索窗口升级设计：概念抽取兜底（#106）+ 自适应扩展深度（#107）

状态：**已确认**（用户已审：概念抽取方案 · 默认参数 · 仅 0 命中触发；图：`retrieval-upgrade.svg`）

## 现状痛点

**#106 字面匹配的盲区**：`_match_score` 三档（整名 3.x / 英文 token 2.0 / 定义关键词 1.0）只在用户消息**字面包含**本体名/关键词时命中。用户用同义改述提问（如「图里的人在哪」而非「visual grounding」）→ 命中 0 → 降级为按度数取枢纽中心（`FALLBACK_CENTER_LIMIT`），与话题无关。

**#107 固定 1 跳的两个问题**：L3 只扩 1 跳，预算富余即停——32k 窗口下 6553 token 预算经常用不满一半；而 1M 窗口（GLM 对话）预算 200k，若简单放开多跳又缺护栏（1462 实体 / 1762 本体↔本体关系，2 跳可能拉进半图谱）。

## 确认的设计

### #106 概念抽取兜底层（仅对话路径 answer()）

触发条件：字面匹配 **0 命中**（命中 ≥1 时走现状路径，零额外 LLM 调用）。

1. **LLM 概念抽取（V4-Flash，虚线蓝）**：小 prompt（只有用户消息，无本体名单），抽 3-8 个关键概念词（中英皆可，专有名词保留英文），返回 JSON 数组。
2. **确定性本地匹配（代码裁决）**：概念 ⋈ 本体名/定义**双向包含**打分（概念=名 3.5 / 互含 2.5+ / 原三档照常），种子 = 命中实体（≤10）。
3. **结果**：概念命中 → 并入 L1 种子（后续 L2 命中关系、L3/L4 扩展照常）；无命中或 LLM 不可达/非法 JSON → 降级现状枢纽中心兜底，**对话不中断不报错**。

**裁决权设计（比整表提名更干净）**：LLM 只输出概念词（自由文本），完全不接触实体选择权——种子全部由确定性代码从 active 本体段挑出，铁律天然成立。

### #107 自适应扩展深度

L3/L4 从「固定 1 跳」改为**预算驱动的逐跳扩展**：

```
d = 1 … MAX_DEPTH:
    注入 d 跳邻居本体（度数降序）
    注入 d 跳邻居的关系（本体↔本体 优先）
    预算剩余 > 15% 且 d < MAX_DEPTH 才进 d+1
护栏：注入本体总数 ≤ MAX_INJECTED(400)
```

- 32k 窗口：通常 1 跳即填满，行为与现状一致；
- 1M 窗口：2 跳扩大覆盖，但 MAX_INJECTED 护栏防稀释。

### 可复现性保证（benchmark/compare 不受影响）

`_retrieve_context` 增加可选参数 `extract_concepts=None`：
- 对话 `answer()` → `_generate(..., concept_fallback=True)` 传入概念抽取钩子；
- `run_benchmark` / `compare` **不传** → 四组对照臂与 A/B 对比保持 0 LLM、确定性、可复现。

### stats 新增字段

`depth_reached`（实际扩展到第几跳）、`llm_fallback`（`{used, concepts[], hits}`，前端对话页可见）。
