1这个项目在做什么

一句话：给一个「数字人」装上一套可追溯、可审批、可回滚的本体知识，并让它只按这套知识回答。

「LLM 无终审权」是贯穿全代码的第一原则

所有大模型（V4-Flash / GLM 5.2）在这里都只做提名与生成，最终裁决永远是「确定性代码 + 用户」。一条候选本体必须逐字命中原文、过三关校验、再经人审批，才能进入数字人的知识；模型凭空编造的证据当场丢弃。这让数字人回答时可逐字回指原文——而不是 ChatGPT 式的自信幻觉。

端到端闭环（已全部实现）

配置模型 → 扫描入库（分段·摘要·标签·嵌入）→ 身份预筛（锚点）→ 本体提取（EDC + 三关校验）→ 出题考核 → 二次编排清洗 → 本体装配 → 数字人对话 → 四组对照幻觉基准 → 错误归因与版本管理。

4和别人不一样的地方

以下不是「用了哪个库」，而是这个项目在方法论与工程上的独有设计。

⚖️「LLM 无终审权」铁律 + 三关校验
LLM 只提名，模型输出永远过三层确定性关卡：结构关（闭集枚举/类型/长度）→ 证据关（mention 必须逐字出现在 chunk 原文，幻觉 span 当场丢弃）→ 语义关（去重）。用户是唯一终审点。
🔀异源交叉核验（dual-LLM）
V4-Flash 生成、GLM 5.2 判卷，两个不同模型互相制衡。判卷通道故意不设规则降级——杜绝「同一个模型给自己的输出打分」的同源偏差。代码注释里明确：判卷失败必须抛错，不允许静默自判。
🪟动态检索窗口（非平铺截断）
把本体注入 prompt 不是「取前 N 个」，而是：字面匹配打分（0 LLM）→ 沿关系图 1/2 跳扩展 → 在 20% 预算内按「锚点→命中本体→命中关系→扩展」分层填充。0 命中时再调一次 LLM 抽概念词兜底，但LLM 只出概念、不碰实体选择权。
📊四组对照幻觉基准（A/B 量化）
同一批题跑 G0 裸模型 / G1 仅本体 / G2 仅 RAG / G3 叠加四臂，GLM 判卷后算出本体边际、RAG 边际、总增益，用数据回答「本体到底有没有用」。这是把「防幻觉」做成可复现实验，而非口号。
🎯身份预筛 · 锚点注入（引导非白名单）
提取前先做高频词统计（0 LLM）→ LLM 提名 3~5 个数字人身份 + 锚点本体 → 注入提取 prompt 加速并精简。但锚点是引导不是白名单，锚点外的实体照常提名，全量提取语义不被破坏。
🔍证据可逐字回原文 + 考题考核
每条候选都带 span_start/span_end/span_text，能定位到原文坐标。提取同次调用顺带出 2~3 道题，审批前用题考核候选——答案的 quote 必须逐字命中原文、used 必须命中候选闭集，否则判 fail。
🔄job + 断点续跑 + 断电恢复
一切长操作统一为 job，chunk 级 checkpoint，进程重启后自动续跑。429 限流特判：并发窗口步进下降 1 并重排该 chunk，而非暂停整任务。WS 事件流按 seq 增量补齐，前端断线无缝恢复。
🛠️被实测逼出来的工程细节
Windows SearchIndexer 会把 SQLite WAL 抓进 3.5GB/30s 的爬取循环 → 用 FILE_ATTRIBUTE_NOT_CONTENT_INDEXED 标记数据目录；Ollama 默认 num_ctx=2048 会静默截断注入的本体、破坏幻觉 A/B 基线 → 定制 32k Modelfile 规避。每条都是真实踩坑后的修复。
🔒零依赖降级 + 优雅启动
本地演示模式：内存存储 + hash 嵌入 + 规则摘要，无 PG、无 key 也能跑通全链路。WSL2/Ollama 不可用不阻塞启动，嵌入自动降级 hash。sudo 密码走 DPAPI 加密缓存（绑定 Windows 用户+本机），不落明文。
🧬本体版本管理（快照 / 回滚）
基准测试的错误归因会提名「标注/修改/删除」本体条目，用户审后一键 merge 前先快照当前本体段，版本 v+1 落库；任意版本可回滚，回滚前自动再快照（回滚本身也可逆）。
